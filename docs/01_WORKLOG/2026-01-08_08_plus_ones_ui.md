## Key Design Decisions

### 1. Inline CSS and JavaScript

**Decision:** Keep CSS and JavaScript inline in the template  
**Rationale:**
- No external file requests (faster page load)
- Single file deployment
- Meets <2s page load target
- Total added size: ~6KB (CSS + JS)

### 2. Progressive Enhancement

**Decision:** Form works without JavaScript, enhanced with JS  
**Rationale:**
- Accessibility for users with JS disabled
- Server-side validation is authoritative
- Client-side validation improves UX
- Follows web standards best practices

### 3. Mobile-First CSS

**Decision:** Base styles for mobile, media queries for larger screens  
**Rationale:**
- Most guests will use mobile devices
- Progressive enhancement approach
- Simpler CSS cascade
- Better performance on mobile

### 4. Conditional Rendering

**Decision:** Only show plus ones field if max_plus_ones > 0  
**Rationale:**
- Cleaner UI when not applicable
- Reduces confusion
- Template logic is simple
- Matches backend validation

### 5. Auto-Disable on "No" Response

**Decision:** Automatically disable and reset plus ones when "No" selected  
**Rationale:**
- Prevents invalid submissions
- Clear visual feedback
- Matches backend auto-correction logic
- Improves user experience

## Technical Notes

### Template Data Requirements

The template expects `RSVPPageData` with:
- `Event` - Event details
- `Invite` - Invite with MaxPlusOnes field
- `ExistingRSVP` - Optional existing RSVP for pre-population
- `Token` - Invite token for form action URL
- `DeadlinePassed` - Boolean to hide form
- `EventPassed` - Boolean to hide form

### Form Submission

The form submits to `POST /rsvp/{token}` with:
- `response` - Radio button value (yes/maybe/no)
- `plus_ones` - Number input value
- Additional fields for preference questions (future story)

### Browser Compatibility

- Modern browsers: Full functionality
- Older browsers: Graceful degradation
- No JavaScript: Server-side validation only
- Mobile browsers: Touch-optimized

## Lessons Learned

1. **Template Testing:** Existing integration tests validate template rendering, so no new template-specific tests were needed.

2. **Progressive Enhancement:** Starting with working HTML form, then adding CSS and JS enhancements is the right approach.

3. **Mobile-First:** Designing for mobile first makes responsive design simpler and more maintainable.

4. **Inline Assets:** For small amounts of CSS/JS, inline is faster than external files due to eliminating HTTP requests.

5. **Accessibility First:** Building accessibility in from the start is easier than retrofitting it later.
