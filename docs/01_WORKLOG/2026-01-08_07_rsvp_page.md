## Key Design Decisions

### 1. Template Loading Strategy

**Decision:** Load templates at server startup, inject into handler  
**Rationale:**
- Templates parsed once, not on every request
- Allows template injection for testing
- Fallback HTML for tests without template files
- Production uses real templates

### 2. Error Handling

**Decision:** Use specific HTTP status codes for different error conditions  
**Mapping:**
- 404 Not Found - Invalid/not found token
- 403 Forbidden - Revoked invite
- 410 Gone - Expired token, cancelled/archived event
- 500 Internal Server Error - System errors

**Rationale:**
- Clear semantic meaning
- Allows clients to handle errors appropriately
- Follows HTTP standards

### 3. Invite Status Tracking

**Decision:** Automatically mark invite as "viewed" when page loads  
**Rationale:**
- Provides analytics on invite engagement
- Non-blocking (errors are logged but don't fail the request)
- Follows invite state machine

### 4. Mobile-First CSS

**Decision:** Inline CSS in template, mobile-first approach  
**Rationale:**
- No external CSS file to load (faster)
- Mobile base styles, progressive enhancement for larger screens
- Meets performance target (<2s page load)
- Single file for easy deployment

### 5. Timezone Handling

**Decision:** Server-side timezone conversion using event's timezone  
**Rationale:**
- Reliable, no JavaScript required
- Works for all users
- Can be enhanced with client-side conversion later
- Displays in event's local time by default

## Technical Notes

### Template Data Structure

The `RSVPPageData` struct provides all necessary data to the template:
```go
type RSVPPageData struct {
    Event          *models.Event
    Invite         *models.Invite
    ExistingRSVP   *models.RSVP
    Questions      []*models.PreferenceQuestion
    Token          string
    DeadlinePassed bool
    EventPassed    bool
    LocalStartTime string
    LocalEndTime   string
    TimeUntilEvent string
    CanUpdate      bool
    ErrorMessage   string
}
```

### Route Pattern

The route uses chi's URL parameter extraction:
```go
GET /rsvp/{token}
```

Token is extracted with: `chi.URLParam(r, "token")`

### Template Fallback

The handler includes fallback HTML for testing without template files:
- Displays basic event information
- Shows error messages
- Allows tests to run without template dependencies

## Lessons Learned

1. **Mock Interface Conflicts:** Had to rename mock types to avoid conflicts with existing test mocks in the same package. Used `mockRSVP*` prefix for clarity.

2. **Error Type Consistency:** Changed RSVP repository to return `NotFoundError` instead of `sql.ErrNoRows` for consistency with other repositories. This required updating existing tests.

3. **Variable Shadowing:** Variable named `token` shadowed the `token` package import. Renamed to `inviteToken` to avoid confusion.

4. **Template Testing:** Integration tests need to explicitly load templates using `template.ParseFiles()` and inject via `SetTemplates()` method.

5. **Repository Error Handling:** When no rows are found, repositories should return domain-specific errors (`NotFoundError`) rather than database-specific errors (`sql.ErrNoRows`) for better abstraction.
